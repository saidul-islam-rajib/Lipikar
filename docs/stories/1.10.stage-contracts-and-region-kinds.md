# Story 1.10 — Stage contracts and region kinds

**Status:** Review
**Epic:** 001 — Foundation and measurement
**Stage:** infra
**Depends on:** 1.2
**Branch:** `story/1.10-stage-contracts-and-region-kinds`

## Context
The epic's stated outcome includes "a working, tested, CPU-only skeleton for every pipeline stage",
and `docs/architecture.md` §3 specifies the dataclasses stages exchange — but no story owned them.
Stages that communicate through loose dicts lose their type contracts exactly when a pipeline gets
big enough for that to matter (R10.2).

## Acceptance criteria

1. Every dataclass in architecture §3 exists as a frozen dataclass in `lipikar/contracts.py`.
2. `Field.verified` defaults to `False` — nothing is authoritative by default (R00.6).
3. Contracts are immutable: assignment raises.
4. Region kinds come from configuration as a closed set, and an unlisted kind is rejected (R70.2).
5. `thumbprint` is among the configured kinds, so those regions can be excluded from recognition.

## Technical notes

**`Polygon` and `Transform` were referenced but never defined** in architecture §3. They are
implemented here minimally — `Polygon` as a tuple of integer `Point`s, `Transform` as a matrix — with
no behaviour, because the geometry belongs to Epic 004. Flagged for Architect confirmation.

Dataclasses holding `np.ndarray` use `eq=False`. Architecture §3 writes `@dataclass(frozen=True)`,
but generated `__eq__` on an array field raises `ValueError: truth value of an array is ambiguous`
the first time two pages are compared. Frozen is preserved; only equality is dropped.

**Gate decision:** **CONCERNS** — reviewed by QA (Sharmin), 2026-08-21, commit `8247e48`.

I hand-diffed `lipikar/contracts.py` against `docs/architecture.md:162-208`: all six specified
dataclasses are present with identical field names, order and annotations, including
`verified: bool = False`. The `eq=False` deviation is justified and documented. I re-ran the
consolidated claim on the second interpreter myself — Python 3.11.9, 102 passed, lint and types
clean. R20.3 is handled well by design: `Line` carries an explicit integer `reading_order` and has
no x-coordinate field at all, so there is nothing to sort by.

Two gaps, both found by executing the contracts rather than reading them.

**Findings:**

- **med** — `lipikar/contracts.py:49` and `:59`: AC4 says region kinds are a closed set and an
  unlisted kind is rejected, but that holds only if a caller remembers `validate_kind`. I confirmed
  `Region(kind="marginalia", ...)` and `Line(region_kind="not_a_kind", ...)` both construct without
  error — and the story's own test at `test_contracts.py:53` constructs `Region` directly, so the
  suite demonstrates the bypass. `binnas` produces these in Epic 005; a `thumbprint` region
  mislabelled `body` sends biometric data into recognition instead of excluding it (R30.5).
- **med** — `lipikar/contracts.py:27-45, 53-60`: `frozen=True` is shallow. Verified live:
  `page.image[0,0] = 255` succeeds, `transform.matrix[0,0] = 99.0` succeeds, and because the array
  is stored by reference the mutation also changes **the caller's original array**. AC3's
  "contracts are immutable" is true only for attribute rebinding; every meaningful payload stays
  writable and aliased, and with `eq=False` there is not even an equality check to notice. Fix:
  `flags.writeable = False` in `__post_init__`.
- low — `tests/unit/test_contracts.py:25-34`: frozenness is tested for `Field` only; the four
  `eq=False` classes — where a hand-edited decorator makes a mistake most likely — are untested.
- low — commit `8247e48` vs story lines 33-34: the commit also changed `README.md`, the epic file
  (renumbering the whole story table), and added `tests/integration/test_measurement_path.py`, which
  exercises the 1.3-1.7 measurement path rather than contracts. None appear in the Files list and
  "Deviations" records only the two contract decisions (R00.2). I reviewed that integration test
  under this gate so it is not left ungated — it is sound.
- low — `lipikar/contracts.py:31-36`: `Page` carries no `writer_id`, so R40.2's writer-disjointness
  cannot be expressed. Same gap as `ManifestEntry` in the 1.6 gate; raise with the Architect
  alongside the `Polygon`/`Transform` confirmation this story already filed.
