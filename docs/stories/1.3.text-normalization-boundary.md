# Story 1.3 — Text normalization boundary

**Status:** Done
**Epic:** 001 — Foundation and measurement
**Stage:** shuddhi
**Depends on:** 1.1
**Branch:** `story/1.3-text-normalization-boundary`

## Context
Un-normalized Bengali produces two byte sequences that render identically, so a textually correct
prediction can score as wrong. The fix is one normalization boundary applied at ingestion, not a
normalization call sprinkled through comparison code.

## Acceptance criteria

1. `normalize` applies the configured Unicode form and strips the configured zero-width codepoints,
   in that one place (R20.1, R20.4).
2. An NFD input and its NFC twin are equal after normalization.
3. ZWJ (U+200D) and ZWNJ (U+200C) are removed.
4. The danda । (U+0964) is preserved and is never an ASCII full stop (R20.5).
5. Conjuncts, pre-base vowel signs, and mixed Bengali/ASCII digits survive unchanged.
6. An unsupported normalization form raises rather than silently passing text through.

## Technical notes

Stripping happens **before** normalization so the composition step sees the final character
sequence. The policy values — form, zero-width codepoints, danda codepoint — come from
`configs/default.yaml` under `text:`; the codepoints are stored as hex strings because an invisible
character in a config file is unreviewable.

The recorded policy lives in `docs/DATA.md` (R20.4).
