## Test quality assessment

This is the strongest test module in the epic. Every mutation I introduced was caught, and the tests
assert behaviour rather than absence of exceptions.

Two things I specifically checked for and did not find: a test that normalizes both sides and then
compares (which would be tautological), and a test that stubs the config instead of using the real
one. `test_nfd_input_normalizes_equal_to_its_nfc_twin` guards against the first by asserting the
inputs differ before asserting the outputs match; the `config` fixture in `tests/conftest.py:15-17`
loads the repository's actual `configs/default.yaml`, so the tests exercise the shipped policy
values rather than invented ones.

The one constructed `TextConfig` (`test_text.py:49-53`) is for the negative case only, and it
inherits the real zero-width and danda values from the loaded config rather than hardcoding them.
That is the right shape.

Ordering detail worth recording as correct: stripping happens *before* normalization (`text.py:20-21`),
so composition sees the final character sequence. Reversing that order would leave a ZWJ sitting
between a consonant and its hasanta during composition. The story called this out and the code does
it.

## Findings

None at or above low severity. I looked specifically for:

- a second normalization path — none exists (single call site verified by grep);
- normalization at comparison time rather than ingestion — the metrics module deliberately does
  *not* normalize (`metrics.py:39`, `:44` docstrings say inputs must already be normalized), which
  is what R20.1 asks for;
- silently swallowed decode errors (R10.6) — none; the only failure path raises `TextPolicyError`;
- transliteration in stored data (R20.8) — none; Bengali is stored as Bengali.
