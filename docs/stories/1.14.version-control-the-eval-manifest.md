## Context
Story 1.6 built a working integrity check — QA tampered with real manifests six ways and the code
caught every accidental edit. But the manifest is placed under gitignored `data/`, while R40.1
requires it in `configs/`, so the frozen eval set currently has no version-controlled definition and
its only guarantee is a checksum stored inside the file it protects. Two acceptance criteria also
have an untested second half.

## Acceptance criteria

1. **(Needs a decision first.)** The frozen eval manifest lives in `configs/` under version control,
   per R40.1, or the deviation is recorded as an ADR in `docs/architecture.md` with Architect and
   human sign-off. Dev must not decide this unilaterally (R00.1).
2. If the manifest moves to `configs/`: `.gitignore` permits it, `scripts/check_no_sensitive_files.py`
   still passes on the tracked tree, and a test asserts the committed manifest loads and passes its
   integrity check.
3. `test_removing_an_entry_is_detected` exists and passes (AC3 of story 1.6, currently untested).
4. `test_hash_algorithm_mismatch_is_rejected` exists and passes (AC6 of story 1.6, currently
   untested; `manifest.py:88` is uncovered).
5. `test_renaming_a_page_id_is_detected` exists and passes.
6. Removing `page_id` from `_checksum`'s input, or disabling the hash-algorithm check, causes at
   least one test to fail.
7. `load_manifest` rejects unknown keys at the document level and inside each entry, matching
   `loader.py:122-125` (R70.5, R10.12).
8. The R40.3 citations at `manifest.py:74` and in story 1.6 are corrected to **R40.1**.

## Technical notes

What QA verified against the real implementation — the code is correct, the tests are thin:

```
remove an entry (AC3)                        detected   <- no test
rename a page_id                             detected   <- no test
swap two content hashes between pages        detected   <- no test
hash-algorithm mismatch (AC6)                detected   <- no test, line 88 uncovered
edit an entry, then recompute the checksum   NOT DETECTED
inject an unknown top-level key              NOT DETECTED
inject an unknown key inside an entry        NOT DETECTED
```

Surviving mutations:

```
M18 manifest.py:86-91  hash-algorithm check disabled -> suite still green
M20 manifest.py:126    page_id dropped from checksum -> suite still green
```

On AC1, the argument for `configs/`: the manifest holds only opaque page IDs and hex digests — no
transcription, no path outside the ID scheme, no party name — so there is no privacy reason it
cannot be committed. Without committing it, "frozen" means "a checksum inside an untracked file",
and a CER from Epic 006 has no anchor to compare against a CER from Epic 009 (R40.1, R00.9). The
in-file checksum then becomes a second line of defence rather than the only one, and the QA check
"`git diff` the manifest" becomes possible for the first time.

Also raise with the Architect, and decide before the set is frozen rather than after:
**`ManifestEntry` carries no `writer_id`.** R40.2 calls writer-disjoint splits non-negotiable and the
QA checklist requires verifying them by inspecting writer IDs across splits — which this format
cannot express. Adding the field at `schema_version: 1` is cheap; adding it to a frozen artifact
later is a version bump that invalidates prior comparisons. The same gap exists on
`lipikar/contracts.py:31-36` (`Page` has no `writer_id`) — see the 1.10 gate.

## Rules that apply
- R40.1 — the eval set is frozen, versioned by manifest file in `configs/`, and untouchable
- R40.2 — splits are writer-disjoint (the schema question above)
- R00.1 — the spec is the contract; escalate rather than deviate silently
- R00.9 — reproducibility
- R70.5 / R10.12 — reject unknown keys, one way of doing each thing

## Testing requirements
- Named cases: `test_removing_an_entry_is_detected`, `test_hash_algorithm_mismatch_is_rejected`,
  `test_renaming_a_page_id_is_detected`, `test_unknown_manifest_keys_are_rejected`
- Command: `pytest tests/unit/test_manifest.py -q`, then the full `pytest -q`

## Out of scope
- Populating a real eval set (Epic 003)
- Signing the manifest or any cryptographic tamper-proofing beyond the existing checksum
- Binding a `MetricSummary` to a manifest checksum — noted in the 1.7 gate, belongs with the first
  story that reports a metric
