# Story 1.1 — Dev environment and toolchain

**Status:** Draft
**Epic:** 001 — Foundation and measurement
**Stage:** infra
**Depends on:** none
**Branch:** `story/1.1-dev-environment-and-toolchain`

## Context
The repo has a BMAD scaffold and a package skeleton but no working development environment. Nothing
can be implemented or verified until `pytest`, `ruff`, and `mypy` run cleanly on a pinned Python.
This story establishes that floor so every later story can produce the test evidence Rule 50
demands.

## Acceptance criteria

1. A documented virtualenv recipe using Python 3.11 or 3.12 (not the system 3.14) exists in
   `README.md`, and following it produces a working environment.
2. `pyproject.toml` declares the package, its runtime dependencies, and its dev dependencies, with
   `ruff`, `mypy`, and `pytest` configured in that single file — no competing config files.
3. `pytest -q` runs and passes, collecting at least one real test (a placeholder that asserts the
   package imports and that `regex` grapheme matching is available).
4. `ruff check .` and `ruff format --check .` pass on the existing tree.
5. `mypy lipikar` passes on the existing tree.
6. `requirements-dev.txt` or equivalent pins exact versions so the environment is reproducible
   (R00.9).

## Technical notes

**Do not add torch in this story.** Runtime ML dependencies arrive with the stories that need them;
adding an unused 2GB dependency now makes CI slow and the environment fragile. This story installs
only what the metric and text layers require.

Dependencies for now:
- runtime: `regex` (required — `re` cannot match grapheme clusters, see R20.2), `numpy`,
  `pyyaml`, `pydantic` *(only if the Architect's config loader needs it; otherwise omit)*
- dev: `pytest`, `pytest-cov`, `ruff`, `mypy`

**Files to create or modify:**
- `pyproject.toml` — package metadata, `[tool.ruff]`, `[tool.mypy]`, `[tool.pytest.ini_options]`
- `requirements-dev.txt` — pinned dev deps
- `tests/unit/test_smoke.py` — the placeholder test
- `README.md` — the setup recipe section

**Ruff and mypy settings expected:**
```toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.mypy]
python_version = "3.11"
warn_return_any = true
warn_unused_ignores = true
disallow_untyped_defs = true

[tool.pytest.ini_options]
testpaths = ["tests"]
```

**The smoke test must actually verify something (R10.8 / QA test-quality check):**
```python
def test_grapheme_matching_available() -> None:
    """regex must segment a Bengali conjunct as ONE cluster, not three codepoints."""
    import regex
    assert len(regex.findall(r"\X", "ক্ষ")) == 1
    assert len("ক্ষ") == 3          # documents why R20.2 exists
```
This is not a trivial placeholder: it fails if `regex` is missing or if someone swaps it for `re`,
which is exactly the regression that would silently break every metric in the project.

## Rules that apply
- R10.1 — Python 3.11/3.12, single config in `pyproject.toml`
- R10.8 — tests in `tests/unit` run in under 30 seconds, no disk, no network, no GPU
- R00.9 — reproducibility: pinned versions
- R20.2 — the reason `regex` is a hard requirement rather than a convenience

## Testing requirements
- `tests/unit/test_smoke.py::test_package_imports` — every stage subpackage imports
- `tests/unit/test_smoke.py::test_grapheme_matching_available` — as above
- Command: `pytest -q`

## Out of scope
- torch, transformers, opencv, or any ML dependency
- CI configuration (story 1.7)
- The actual metric implementation (story 1.3)
- Pre-commit hooks
