# Story 1.12 — Remove codepoint CER from the shippable metrics surface

**Status:** Draft

> (`docs/qa/gates/1.4.md`). Needs SM/PM sequencing into the epic — QA does not edit the epic file.

## Context
Story 1.4 shipped the correct grapheme-cluster CER, and QA verified it independently on real deed
vocabulary. It also shipped `codepoint_cer` in the same module so that AC2's difference could be
proven in a test rather than asserted in prose — a reasonable call, but it leaves a public function
named like a metric, with a metric's signature, computing the one number this project has decided is
never reportable. The proof is worth keeping; its location is not.

## Acceptance criteria

1. `lipikar.shuddhi.metrics` no longer exports a codepoint-based error rate. Importing
   `codepoint_cer` from it fails.
2. The AC2 proof from story 1.4 survives intact: a test still demonstrates that cluster CER and
   codepoint CER differ on a Bengali conjunct, and that the cluster number is the defensible one.
   The codepoint side is computed inside the test module.
3. The empty-reference convention at `metrics.py:55` is stated in `_error_rate`'s or `grapheme_cer`'s
   docstring, and is covered by a test using a **long** hypothesis against an empty reference, so the
   clamping behaviour is explicit rather than incidental.
4. A test covers insertions against a non-empty reference, including a case where CER legitimately
   exceeds 1.0, documenting that the metric is unbounded above.
5. `grep -rn "codepoint" lipikar/` returns nothing outside a docstring explaining why cluster
   segmentation is used.

## Technical notes

The finding, verbatim from the gate:

> `lipikar/shuddhi/metrics.py:48-50` — `codepoint_cer` is a public, importable function in the
> shippable package, in the same module as `grapheme_cer`, with an identical signature, no leading
> underscore, and no `__all__` restricting it. It measures `tuple(reference)` — codepoints.

Current implementation to relocate:

```python
def codepoint_cer(reference: str, hypothesis: str) -> float:
    """Deliberately wrong for Bengali. Exists so tests can prove the difference (R20.2)."""
    return _error_rate(tuple(reference), tuple(hypothesis))
```

`_error_rate` and `edit_distance` stay in `metrics.py` — they are generic over `Sequence[str]` and
are the shared core. The test module can import `edit_distance` and do its own codepoint
segmentation in two lines, which keeps the contrast honest while keeping the wrong metric out of the
package.

The numbers the relocated test must still reproduce (QA verified all four independently):

| reference | hypothesis | grapheme_cer | codepoint_cer |
|---|---|---|---|
| `ক্ষ` | `ক` | 1.0 | 0.6667 |
| `মৌজা` | `মজা` | 0.5 | 0.25 |
| `খতিয়ান` | `খতিয়া` | 0.25 | 0.1429 |

The `মৌজা` row is the most persuasive and is worth adding to the test alongside the existing
conjunct case: a dropped ৌ matra loses half the word but codepoint CER reports 25%.
