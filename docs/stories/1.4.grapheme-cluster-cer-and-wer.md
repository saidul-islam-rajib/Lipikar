# Story 1.4 — Grapheme-cluster CER and WER

**Status:** Review

**Stage:** shuddhi
**Depends on:** 1.3
**Branch:** `story/1.4-grapheme-cluster-cer-and-wer`

## Context
This is the story the epic exists for. A codepoint-based CER makes a model that systematically drops
matras look accurate, and every decision taken from such a number has to be thrown away along with
the number. The metric ships before any model so there is never a period where a wrong number is the
best available one.

## Acceptance criteria

1. `lipikar.shuddhi.metrics.grapheme_cer` segments with `regex.findall(r"\X", ...)` (R20.2).
2. A test proves cluster CER differs from codepoint CER on a Bengali conjunct, and that the cluster
   number is the defensible one.
3. `word_error_rate` measures whole words using the configured separator.
4. An NFD input and its NFC twin score 0.0 through the real code path — normalize, then measure.
5. Empty-reference behaviour is defined and tested rather than raising a `ZeroDivisionError`.
6. The R20.9 adversarial set is covered.

## Technical notes

Metrics take **already-normalized** text. Normalizing inside the metric would put a second
normalization path in the codebase and would contradict R20.1's "normalize at ingestion, not at
comparison time". AC4 is therefore tested by calling `normalize` and then the metric, which is how
callers must use it.

`codepoint_cer` is shipped deliberately — not for use, but so the difference in AC2 is provable in a
test rather than asserted in a comment.

## QA section
*(QA agent fills this in. Gate: `docs/qa/gates/1.4.md`.)*

**Gate decision:** **CONCERNS** — reviewed by QA (Sharmin), 2026-08-21, commit `399aed2`.

**The metric is correct.** I re-derived AC2 independently rather than trusting the story's table,
extending it to real deed vocabulary: `মৌজা` to `মজা` scores 0.50 by cluster and 0.25 by codepoint,
so codepoint CER halves the apparent damage of a dropped matra — exactly the failure R20.2 exists to
prevent. I swept every `len(`/`list(`/`enumerate(` in `lipikar/` and confirmed every `len()` in the
metric path counts clusters or words, never codepoints. Replacing cluster segmentation with
codepoint segmentation fails five tests.

The concern is placement, not arithmetic.

**Findings:**

- **med** — `lipikar/shuddhi/metrics.py:48-50`: `codepoint_cer` is a public, importable function in
  the shippable package, in the same module as `grapheme_cer`, with an identical signature, no
  leading underscore, and no `__all__` restricting it. Only a docstring stops a wrong number
  reaching a report. I considered the auto-FAIL rule and did **not** FAIL, because nothing reports
  it and the epic's AC1 requires the difference be provable — but the proof belongs in the test
  module, not next to the correct function. This is a judgement call the human may overrule in
  either direction; only they can waive.
- low — `lipikar/shuddhi/metrics.py:55`: `_error_rate` returns a hardcoded `1.0` for an empty
  reference regardless of hypothesis length (R10.4), silently clamping a hallucinated line to the
  same score as a one-cluster insertion.
- low — `tests/unit/test_metrics.py`: no insertion case against a non-empty reference, where CER
  legitimately exceeds 1.0.

**Cross-story hazard recorded here, owned by 1.5:** story 1.5's five-cluster `<unk>` token inflates
this metric — measured `grapheme_cer("৺", decode((0,), charset)) == 5.0`.
