# Story 1.9 — String resources and locale parity

**Status:** Review
**Epic:** 001 — Foundation and measurement
**Stage:** infra
**Depends on:** 1.2, 1.3
**Branch:** `story/1.9-string-resources-and-locale-parity`

## Context
Rule 70 Part B says `bn.yaml` is a real deliverable and not a stub. Left until a UI exists, it
becomes exactly the afterthought R70.9 forbids — English strings hardcoded through the codebase and
a Bengali file retrofitted by machine translation at the end. Building the mechanism now costs
little and makes the rule enforceable from the first user-facing string.

## Acceptance criteria

1. `en.yaml` and `bn.yaml` exist under `lipikar/resources/strings/` and ship with the package.
2. A test asserts the two locales have identical key sets (R70.13).
3. The mandatory assistive-output notice is a resource in both locales (R70.14, R00.6).
4. Lookup interpolates **named** placeholders and works when a locale reorders them (R70.10).
5. A missing key raises rather than rendering the key back to a user (R70.12).
6. Bengali values are NFC-normalized and are genuine translations, not copies of the English.

## Technical notes

Keys are `<stage>.<component>.<intent>` (R70.11) and flattened from nested YAML, so the files stay
readable while the API stays a flat stable key.

`nazir.review.progress` is the deliberate proof of AC4: English reads "{done} of {total} fields
verified", Bengali puts `{total}` first. Positional or concatenated assembly would produce broken
Bengali grammar, which is why R70.10 exists, and the test asserts the reordering rather than
describing it.

Resource values are normalized through `lipikar.shuddhi.text.normalize` — the same boundary as every
other string in the system, not a second NFC call.

## Dev section

**Completion notes:**
The first implementation normalized resource values with its own `unicodedata.normalize` call. mypy
rejected it on a `Literal` mismatch, which surfaced that it was a second normalization path — it now
calls story 1.3's boundary. This is R10.12 catching a duplicate before it became convention.

**Bengali review is outstanding.** R70.9 requires that translations be reviewed by someone who reads
Bengali and forbids shipping machine-translated UI text. The five `bn.yaml` values were written as
part of this story and have **not** been reviewed by a Bengali reader. They are seed content and the
mechanism around them is what this story delivers. This is flagged for the human, not waived.

## QA section
*(QA agent fills this in. Gate: `docs/qa/gates/1.9.md`.)*

**Gate decision:** **CONCERNS** — reviewed by QA (Sharmin), 2026-08-21, commit `efcae4f`.

All six acceptance criteria are met and the mechanism is right. I checked the bytes directly: both
locale files are UTF-8 without BOM, NFC on disk, LF endings. I read all five strings in both locales
and every one frames output as provisional — R00.6 and R70.14 are satisfied structurally, since the
assistive notice is a single key that cannot be weakened in one surface and not another.
`test_named_placeholders_survive_reordering` is the model for testing a rule rather than a line: it
asserts the Bengali actually renders `{total}` before `{done}`.

**Findings:**

- **med** — `tests/unit/test_strings.py:44-46` vs `lipikar/strings.py:69`: AC6's NFC guarantee is
  asserted about the **file**, not the code path. Because `bn.yaml` is already NFC, the assertion
  passes either way — I deleted the `normalize()` call and the full suite stayed green. The test
  cannot fail for either reason it exists: a loader regression, or an NFD value added later by a
  contributor whose editor decomposes. Fix: load a fixture locale containing a deliberately NFD
  value through `load_catalog` and assert the result is NFC.
- **med** — `lipikar/resources/strings/bn.yaml`: R70.9 requires Bengali translations be reviewed by
  someone who reads Bengali and forbids shipping machine-translated UI text; that review has not
  happened. Dev flagged this openly and declined to waive it, which is correct. No live harm — no
  surface renders these yet — but the assistive notice is the sentence telling a user not to rely on
  output for a legal purpose, so its Bengali must be right before Epic 009.
- low — `lipikar/strings.py:31-35` and `config/schema.py:40-43`: `load_catalog` accepts any locale
  string and never consults `StringsConfig`; `default_locale` and `locales` are configured but no
  module reads them.
- low — `lipikar/strings.py:50`: extra placeholders are silently ignored, the inverse of the
  missing-placeholder case which is correctly caught. R70.11 treats a key as an API, so drift should
  be visible in both directions.
