**Decision:** CONCERNS
**Reviewed by:** QA (Sharmin) · **Date:** 2026-08-21 · **Commit:** `8247e48`

invariant the whole human-in-the-loop posture rests on. Two gaps I confirmed by executing the code:
the "closed set" of region kinds is not enforced at construction, and immutability stops at the
attribute — the array payloads stay writable.

## Test quality assessment

Focused and behavioural. `test_extracted_fields_are_unverified_by_default` is correctly isolated as
its own case rather than folded into a constructor test — Dev's reasoning that it is the invariant
the human-in-the-loop posture rests on is right, and mutation M5 confirms it bites.
`test_configured_region_kinds_are_accepted` iterates the real configured set rather than a
hardcoded list, so adding a kind to `configs/default.yaml` cannot leave the test stale.

Two weaknesses:

1. `test_configured_region_kinds_are_accepted:53` constructs `Region(kind=kind, ...)` **directly**,
   never through `validate_kind`. So the test's own usage demonstrates the pattern that bypasses the
   closed set. Nothing in the suite would fail if every future caller did the same.
2. `test_contracts_are_frozen` tests one class (`Field`) and one attribute. `Page`, `RestoredPage`,
   `Line` and `Transform` — the four with `eq=False` and array payloads, i.e. the ones where a
   subtle mistake is most likely — are unverified for frozenness. `test_line_carries_its_polygon_in_page_space`
   asserts `line.image.dtype == np.uint8` on an array the test itself created, so it proves nothing
   about the contract.
