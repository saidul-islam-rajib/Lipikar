## Context
Story 1.10 landed the architecture §3 contracts with `verified=False` by default, which is the
invariant the human-in-the-loop posture rests on. But QA found the closed set of region kinds is
enforced only if a caller remembers to call a free function — `Region(kind="marginalia")` constructs
happily — and `frozen=True` stops at the attribute, leaving every image, mask and matrix writable
and aliased to the caller's array. Both are cheap to fix now and expensive after five stages depend
on them.

## Acceptance criteria

1. Constructing a `Region` or a `Line` with a kind outside the configured set raises. A test asserts
   `Region(kind="marginalia", ...)` **raises**, not merely that `validate_kind` rejects it.
2. Every configured kind still constructs successfully, driven from `configs/default.yaml` rather
   than a hardcoded list (as the current test correctly does).
3. In-place mutation of an array payload raises: `Page.image`, `RestoredPage.image`,
   `RestoredPage.ink_mask`, `RestoredPage.annotation_mask`, `Line.image`, and `Transform.matrix`.
4. Constructing a contract does not leave the caller's original array mutable through the contract,
   and mutating the caller's array afterwards is either prevented or explicitly documented.
5. Frozenness (attribute assignment raises) is tested across **all** contract dataclasses, not only
   `Field`, with particular attention to the four carrying `eq=False`.
6. `Field.verified` still defaults to `False` and its dedicated test still passes unchanged.
7. Story 1.10's file list is corrected to include `README.md`,
   `docs/epics/epic-001-foundation-and-measurement.md`, and
   `tests/integration/test_measurement_path.py`.

## Technical notes

What QA executed:

```
== AC4 of story 1.10: is the closed set enforced at construction? ==
  Region(kind='marginalia', ...)       constructed OK -> 'marginalia'    NOT rejected
  Line(region_kind='not_a_kind', ...)  constructed OK -> 'not_a_kind'    NOT rejected

== AC3 of story 1.10: how deep does immutability go? ==
  page.page_id = "p2"      -> raises FrozenInstanceError      (holds)
  page.image[0,0] = 255    -> SUCCEEDED                       (payload mutable)
  caller's original array also changed                        (aliased, not copied)
  transform.matrix[0,0] = 99.0 -> SUCCEEDED
```

For AC1, the constructor needs access to `BinnasConfig`. Two shapes, pick one and apply it
consistently (R10.12):

- `__post_init__` calling `validate_kind`, with the config threaded in as a field or via an explicit
  factory; or
- module-level factories `make_region(kind, polygon, config)` / `make_line(..., config)` with the raw
  constructors treated as private.

The second keeps `contracts.py` free of a config dependency, which matters because `contracts.py` is
imported by every stage. Prefer it unless the Architect says otherwise. Note that the current test
`test_configured_region_kinds_are_accepted:53` constructs `Region` directly — that line is itself a
demonstration of the bypass and should move to the factory.

For AC3, set `flags.writeable = False` on each ndarray in `__post_init__`. No `object.__setattr__`
gymnastics are needed — the flag lives on the array, not on the dataclass field. Decide deliberately
whether to copy on construction (safe, costs memory per page) or to freeze the caller's array in
place (cheap, surprising); document whichever is chosen in the class docstring, since the dtype and
coordinate contracts already live there.

Why this matters concretely: a `thumbprint` region mislabelled as `body` sends biometric data into
recognition rather than excluding it (R30.5), and a stage that "just normalises the mask in place"
silently corrupts an upstream stage's data with no equality check to notice, because these classes
carry `eq=False`.

Also raise with the Architect, tracked identically in the 1.6 gate: **`Page` carries no `writer_id`**
(`contracts.py:31-36`). R40.2 makes writer-disjoint splits non-negotiable and the QA checklist
requires verifying them by inspecting writer IDs across splits. Neither `Page` nor `ManifestEntry`
can express a writer today.
