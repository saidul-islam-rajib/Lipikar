## Test quality assessment

The guard tests are behavioural and specific: `test_anything_under_data_is_rejected` asserts the
returned violation's `path` equals the input rather than merely that a list is non-empty, and
`test_windows_separators_do_not_bypass_the_guard` pins a normalization that previously existed only
as prose in the script. `test_legitimate_paths_are_allowed` is the important negative case — a guard
that blocks everything would pass the positive tests alone.

`test_tracked_tree_is_clean` is a genuinely good idea: it runs the guard over the real tracked file
list, so the suite goes red if anyone ever commits something the guard would reject.

Three gaps:

1. The tests never exercise `main()`, so no test asserts the **exit code**, which is the only thing
   CI actually consumes. `find_violations` returning a list is not the same contract as "the build
   fails". I verified the exit codes by hand instead.
2. `test_guard_fails_closed_when_its_config_is_missing` covers a missing file; ADR-004 also promises
   failing closed on a **malformed** config. A `configs/privacy_guard.json` with a missing key raises
   `KeyError` (`check_no_sensitive_files.py:34-40`) — correct, but untested.
3. `test_tracked_tree_is_clean` and the `guard` fixture read from disk and shell out to `git`. I
   confirmed this by running the suite in a copy of the tree outside a git work tree, where that test
   is the only failure. R10.9 reserves `tests/unit` for pure functions with no disk and no network.

| med | `configs/privacy_guard.json:4-6` (and the mirrored list in `.gitignore:236-243`) | `restricted_suffixes` omits `.heic`/`.heif`, `.gif`, and every archive and array format. Verified live: `scans/deed.heic`, `scans/deed.gif`, `corpus/deeds.zip`, and `notebooks/deed_crops.npy` are all **ALLOWED**. | `.heic` is the default photo format on iPhones, and this project's inputs are phone photographs of deeds — this is the single most likely real-world leak path, not a hypothetical one. `.zip` is the obvious delivery format for a batch from a records office. `.npy`/`.npz` is exactly the derived cache of line crops that R30.7 tells us to delete rather than scatter, and it can contain readable deed imagery. R30.1 says a leak here cannot be undone. | Add `.heic`, `.heif`, `.gif`, `.jp2`, `.avif`, `.dng`, `.raw`, `.cr2`, `.nef` to `restricted_suffixes`; add `.zip`, `.7z`, `.rar`, `.tar`, `.tar.gz` and `.npy`, `.npz` as new categories with their own reason strings. Mirror the same additions into `.gitignore` so the two lists cannot drift. Add a parametrized test per new suffix. |
| low | `tests/unit/test_privacy_guard.py` | No test invokes `main()`, so the exit code — the only signal CI consumes — is unasserted.
