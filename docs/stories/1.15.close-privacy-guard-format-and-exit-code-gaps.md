## Context
Story 1.8 made the privacy guard a job that blocks, and QA confirmed end to end that a genuinely
staged file under `data/` fails the guard with exit 1. But the guard's extension list omits `.heic` —
the default photo format on every iPhone — on a project whose inputs are phone photographs of legal
documents. R30.1 says a leak into git history cannot be undone by a later delete, so the gap matters
more than its size suggests.

## Acceptance criteria

1. `configs/privacy_guard.json` blocks `.heic`, `.heif`, `.gif`, `.jp2`, `.avif`, and the common raw
   camera formats `.dng`, `.raw`, `.cr2`, `.nef`, outside `allowed_image_prefixes`.
2. Archive formats `.zip`, `.7z`, `.rar`, `.tar`, `.tgz` are blocked with their own reason string.
3. Array/cache formats `.npy`, `.npz` are blocked with their own reason string (R30.7 — derived
   caches containing readable deed content).
4. `.gitignore` is updated with the same additions, so the two lists cannot drift.
5. A parametrized test covers every newly blocked suffix, including at least one uppercase variant.
6. Tests invoke `main()` and assert the **exit code**: `1` for a violating path, `0` for a clean
   path, non-zero when the config is missing, and non-zero when the config is malformed
   (ADR-004 promises fail-closed on both).
7. `test_tracked_tree_is_clean` moves to `tests/integration/` (it shells out to `git ls-files` and
   reads from disk, which R10.9 excludes from `tests/unit`).
8. `python scripts/check_no_sensitive_files.py --all` still exits 0 on the tracked tree.

## Technical notes

QA probed the guard live. Blocked correctly:

```
data/raw/page_0142.jpg   blocked      scans/deed.JPG   blocked (case handled, .suffix.lower())
deed.png                 blocked      data/.gitkeep    allowed (intended)
```

Allowed, and should not be:

```
scans/deed.heic     ALLOWED      scans/deed.HEIC          ALLOWED
scans/deed.gif      ALLOWED      corpus/deeds.zip         ALLOWED
notebooks/deed_crops.npy  ALLOWED
```

The guard stays **stdlib-only and JSON-configured** per ADR-004 — it must run in a bare shell, in a
pre-commit hook outside an activated venv, and in CI before `pip install`. Do not add a dependency
and do not convert the config to YAML; ADR-004 rejects both explicitly and records why.

Note the ordering in `find_violations` (`check_no_sensitive_files.py:61-76`): `allowed_basenames` is
checked **first**, before `forbidden_prefixes`. That is intentional so `data/**/.gitkeep` survives,
but it means any basename added to that list becomes allowed *everywhere*, including under `data/`.
Keep the list minimal and do not add a bare `README.md`.

For AC6, the tests can drive `main()` with `monkeypatch.setattr(sys, "argv", [...])` and assert the
return value, and can point `CONFIG_PATH` at a `tmp_path` file for the malformed case. Today no test
touches `main()` at all, so the only signal CI actually consumes — the exit status — is unasserted;
a refactor that returned 0 on violations would keep every existing test green.

**Files to create or modify:**
- `configs/privacy_guard.json` — new suffixes and reason strings
- `.gitignore` — mirrored additions
- `tests/unit/test_privacy_guard.py` — new suffix cases, `main()` exit-code cases

## Rules that apply
- R30.1 — nothing real enters version control; history is effectively permanent
- R30.2 — only redacted or synthetic samples are publishable
- R30.7 — delete derived caches containing readable text; do not scatter copies
- ADR-004 — the guard is stdlib-only, JSON-configured, and fails closed
- R10.9 — `tests/unit` is pure functions, no disk, no network

## Testing requirements
- Named cases: parametrized `test_camera_and_archive_formats_are_rejected`,
  `test_main_exits_nonzero_on_violation`, `test_main_exits_zero_on_clean_paths`,
  `test_main_exits_nonzero_when_config_is_malformed`
- Command: `pytest tests/unit/test_privacy_guard.py tests/integration -q`, then the full `pytest -q`,
  then `python scripts/check_no_sensitive_files.py --all`

## Out of scope
- Content scanning (detecting deed text inside `.md`/`.json`/`.csv`). Worth a separate story — the
  guard matches paths only, and R30.1 also forbids deed content in commit messages and story files,
  which no automated control currently covers.
- Pre-commit hook installation (still the developer's choice, per story 1.8)
- Release and deployment workflows
