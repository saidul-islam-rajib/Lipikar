## Context
This is the story the epic exists for. A codepoint-based CER makes a model that systematically drops
matras look accurate, and every decision taken from such a number has to be thrown away along with
the number. The metric ships before any model so there is never a period where a wrong number is the
best available one.

## Acceptance criteria

1. `lipikar.shuddhi.metrics.grapheme_cer` segments with `regex.findall(r"\X", ...)` (R20.2).
2. A test proves cluster CER differs from codepoint CER on a Bengali conjunct, and that the cluster
   number is the defensible one.
3. `word_error_rate` measures whole words using the configured separator.
4. An NFD input and its NFC twin score 0.0 through the real code path — normalize, then measure.
5. Empty-reference behaviour is defined and tested rather than raising a `ZeroDivisionError`.
6. The R20.9 adversarial set is covered.

## Technical notes

Metrics take **already-normalized** text. Normalizing inside the metric would put a second
normalization path in the codebase and would contradict R20.1's "normalize at ingestion, not at
comparison time". AC4 is therefore tested by calling `normalize` and then the metric, which is how
callers must use it.

`codepoint_cer` is shipped deliberately — not for use, but so the difference in AC2 is provable in a
test rather than asserted in a comment.
