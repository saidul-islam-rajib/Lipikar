**Decision:** CONCERNS
**Reviewed by:** QA (Sharmin) · **Date:** 2026-08-21 · **Commit:** `07de4ff`

## Test quality assessment

The tamper tests are well constructed. `test_editing_an_entry_is_detected` writes a real manifest,
round-trips it through `yaml.safe_load`, mutates one field, writes it back, and loads — exercising
the same path a careless edit takes rather than forging a bad checksum directly. That is the
difference between testing the mechanism and testing the assertion.

Two mutations survived, both pointing at the same shape of gap: the tests cover the *first* half of
each two-part acceptance criterion.

- **M18** — deleting the hash-algorithm mismatch check leaves the suite green (matches uncovered
  line 88). AC6 names two mismatches; one is tested.
- **M20** — removing `page_id` from the checksum input leaves the suite green. Every tamper test
  mutates `content_hash`; none mutates `page_id`. So the property "which hash belongs to which page
  is protected" is implemented but unpinned. I verified by hand that the real code does detect a
  rename — but nothing stops a refactor from losing it.

| med | Story `1.6:28-31` and repo-wide (`configs/` contains no manifest) | R40.1 states the eval set is "versioned by manifest file (a list of page IDs and their hashes) **in `configs/`**". The story instead places the manifest under `data/`, which is gitignored, and no manifest exists in the repo. | The frozen eval set has no version-controlled definition. Its integrity rests entirely on a checksum stored *inside the same file* — and I confirmed live that editing an entry and recomputing that checksum is **not detected**. So the guarantee is "detects accidental drift in an untracked file", not "the eval set is frozen". Comparing a CER from Epic 006 to one from Epic 009 has no anchor, contradicting R40.1 and R00.9. The manifest contains only opaque IDs and hashes, so there is no privacy reason it cannot be committed. Separately, this is a deviation from a binding rule decided inside a Dev story rather than escalated (R00.1), and the story's "Deviations from story: none" does not record it. | Commit the manifest to `configs/` as R40.1 requires (e.g. `configs/eval_manifest.v1.yaml`), and add `.gitignore` negation if needed. Then the QA check "git diff the manifest" becomes possible, and the in-file checksum becomes a second line of defence rather than the only one. If `data/` is genuinely preferred, that needs Architect sign-off and an ADR, not a story-level decision. |
| med | `tests/unit/test_manifest.py` | Two acceptance criteria are half-tested. AC3 says "adding **or removing**" — only adding is tested.
