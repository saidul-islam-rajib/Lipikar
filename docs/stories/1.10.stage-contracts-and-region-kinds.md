# Story 1.10 — Stage contracts and region kinds

**Status:** Review
**Epic:** 001 — Foundation and measurement
**Stage:** infra
**Depends on:** 1.2
**Branch:** `story/1.10-stage-contracts-and-region-kinds`

## Context
The epic's stated outcome includes "a working, tested, CPU-only skeleton for every pipeline stage",
and `docs/architecture.md` §3 specifies the dataclasses stages exchange — but no story owned them.
Stages that communicate through loose dicts lose their type contracts exactly when a pipeline gets
big enough for that to matter (R10.2).

## Acceptance criteria

1. Every dataclass in architecture §3 exists as a frozen dataclass in `lipikar/contracts.py`.
2. `Field.verified` defaults to `False` — nothing is authoritative by default (R00.6).
3. Contracts are immutable: assignment raises.
4. Region kinds come from configuration as a closed set, and an unlisted kind is rejected (R70.2).
5. `thumbprint` is among the configured kinds, so those regions can be excluded from recognition.

## Technical notes

**`Polygon` and `Transform` were referenced but never defined** in architecture §3. They are
implemented here minimally — `Polygon` as a tuple of integer `Point`s, `Transform` as a matrix — with
no behaviour, because the geometry belongs to Epic 004. Flagged for Architect confirmation.

Dataclasses holding `np.ndarray` use `eq=False`. Architecture §3 writes `@dataclass(frozen=True)`,
but generated `__eq__` on an array field raises `ValueError: truth value of an array is ambiguous`
the first time two pages are compared. Frozen is preserved; only equality is dropped.
