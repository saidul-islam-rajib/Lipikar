### I re-derived AC2 myself on real deed vocabulary

The story's table uses `ক্ষ` → `ক`. I did not want to rely on a single hand-picked example, so I ran
the shipped functions over words that actually appear in land deeds:

```
ref='ক্ষ'      hyp='ক'        clusters=('ক্ষ',)                grapheme=1.0000  codepoint=0.6667
ref='মৌজা'     hyp='মজা'      clusters=('মৌ','জা')            grapheme=0.5000  codepoint=0.2500
ref='খতিয়ান'   hyp='খতিয়া'    clusters=('খ','তি','য়া','ন')   grapheme=0.2500  codepoint=0.1429
ref='দাগ ১২৩'  hyp='দাগ ১২৪'  clusters=('দা','গ',' ','১','২','৩') grapheme=0.1667 codepoint=0.1429
```

`মৌজা` → `মজা` is the case that proves the epic's thesis: dropping the ৌ matra loses one of two
perceived characters — a 50% error — but codepoint CER reports **25%**, halving the apparent damage.
That is exactly the "model that drops matras looks accurate" failure R20.2 was written to prevent,
and the shipped `grapheme_cer` reports the defensible number.

## Test quality assessment

Good. The tests assert exact numeric values with visible arithmetic rather than "did not raise", and
several pin the cluster segmentation explicitly (`test_danda_is_a_measured_cluster:58` asserts
`('বা','ক্য','।')`) so a reader can check the denominator by eye. The Dev section records that one
expectation was wrong on first run and the *expectation* was corrected rather than the code — that
is the right direction, and the resulting test is stronger for showing its working.

All three mutations I introduced were caught.

Gap worth naming: `edit_distance` has no test for a pure-insertion case against a non-empty
reference (e.g. `grapheme_cer("কি", "কিছু")`, which should exceed 0 and can exceed 1.0). M24 was
caught, so the algorithm is exercised, but the insertion branch is caught only incidentally.

## Findings

| Sev | Location | What is wrong | How it fails | Suggested fix |
|---|---|---|---|---|
| med | `lipikar/shuddhi/metrics.py:48-50` | `codepoint_cer` is a **public, importable function in the shippable package**, sitting in the same module as `grapheme_cer`, with an identical signature, no leading underscore, and no `__all__` restricting it (`lipikar/shuddhi/__init__.py:3` sets `__all__ = []` but `metrics.py` has none). It measures `tuple(reference)` — codepoints. | Nothing but a docstring stops `from lipikar.shuddhi.metrics import codepoint_cer` and a wrong number reaching an experiment report. My mandate treats codepoint measurement in a metric path as auto-FAIL; I did **not** FAIL because nothing reports it and the epic's AC1 explicitly requires proving the difference, which requires computing it somewhere. But "somewhere" should not be the production metrics module next to the correct function. | Move `codepoint_cer` into `tests/unit/test_metrics.py` as a local helper, or rename it `_codepoint_cer_for_contrast_only` and exclude it from the module's public surface. The AC2 proof is unaffected — the test can define its own two-line codepoint edit rate. **This is a judgement call the human may want to overrule in either direction; only they can waive.** |
| low | `lipikar/shuddhi/metrics.py:55` | `_error_rate` returns a hardcoded `1.0` when the reference is empty and the hypothesis is not, regardless of hypothesis length. | AC5 asks for defined behaviour and this is defined, but the constant is a magic value in code (R10.4) and it silently clamps: a 1-cluster spurious insertion and a 100-cluster hallucination on an empty reference both score `1.0`. For a blank line that the model fills with garbage, the report will understate the damage. | State the convention in the docstring and, if it should stay, source it from `MetricsConfig`. Alternatively return `len(hypothesis)` normalised the same way CER handles insertions elsewhere. Either way, add a test asserting the chosen behaviour for a *long* hypothesis against an empty reference. |
| low | `tests/unit/test_metrics.py` | No test for insertions against a non-empty reference, where CER legitimately exceeds 1.0. | A CER capped at 1.0 by a future "sanity clamp" would not be caught, and callers may reasonably but wrongly assume CER ∈ [0,1]. | Add `assert grapheme_cer("কি", "কিছু") == pytest.approx(1.0)` and one case that exceeds 1.0, documenting that the metric is unbounded above. |
